# Bug reports 
This folder contains bug reports from my manual QA course provided by Microsoft on Coursera.

## Bug report structure 
**Title - the short description of the issue**

**Environment - where it was tested**

**Preconditions - initial state of the application before testing**

**Steps to Reproduce - the steps that have been made during the test**

**Expected result - what should happen according to the specifications**

**Actual result - what actually happened**

**Severity - The level of impact the bug has on the system**
- **High Priority:** Fixed immediately. The bug blocks the system or a main feature of the product.
- **Medium Priority:** Fixed in the next release. Does not block the main features, but needs to be resolved.
- **Low Priority:** Can wait. Does not interfere with the software functionality, but is visible in the UI.

**Priority** - Urgency of fixing the issue (typically assigned by the Product Owner or Manager).
  
**Notes / Evidence - evidence that helps the developer**
